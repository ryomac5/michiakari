全体構成

利用者のブラウザ→ 画面 apps/web　Vercel
利用者のブラウザ→ POST /judge と SSE → 判断エージェント apps/agent　コンテナ→ Claude API

ブラウザはエージェントへ直接つなぎ、判断を SSE で受け取ります。

API キーを持つのはエージェントだけです。画面はキーを一切持ちません。

知見とシナリオは、画面とエージェントの両方が実行時に読みます。

エージェントのコンテナ公開

イメージの中身

定義は infra/agent/Dockerfile です。ビルドの文脈はリポジトリのルートです。

  • Node 24 の型の除去で、TypeScript をそのまま実行します。
  • エージェントが使うワークスペースだけを本番依存で入れます。
  • 知見、シナリオ、ダミー内容、路線データを同梱します。
  • 実行ユーザーは非 root の node です。
  • 待ち受けのポートは PORT で決まり、既定は 8787 です。
  • HEALTHCHECK が /health を定期的に確かめます。

Cloud Run での公開

Cloud Run を例に示します。他のコンテナ環境でも流れは同じです。

以下の PROJECT_ID と REGION は自分の値に置き換えます。

# 1. イメージの置き場所を作る
gcloud artifacts repositories create kansai \
  --repository-format=docker --location=REGION

# 2. ビルドして送る。Cloud Run は amd64 で動く
docker build --platform linux/amd64 -f infra/agent/Dockerfile \
  -t REGION-docker.pkg.dev/PROJECT_ID/kansai/agent:v1 .
docker push REGION-docker.pkg.dev/PROJECT_ID/kansai/agent:v1

# 3. API キーを Secret Manager に入れる。値は標準入力から渡す
gcloud secrets create anthropic-api-key --data-file=-

# 4. デプロイする
gcloud run deploy kansai-agent \
  --image REGION-docker.pkg.dev/PROJECT_ID/kansai/agent:v1 \
  --region REGION \
  --allow-unauthenticated \
  --set-env-vars JUDGE_MODE=claude,CORS_ORIGINS=https://your-app.vercel.app,TRUST_PROXY=true,CONTENT_DIR=packages/schema/test/fixtures/dev-content \
  --set-secrets ANTHROPIC_API_KEY=anthropic-api-key:latest \
  --max-instances 2 \
  --timeout 300

Cloud Run は PORT を自動で渡します。指定は不要です。

TRUST_PROXY=true は必須です。外すと全利用者が同じ接続元に見え、頻度制限が合算されます。

開発者の知見がそろうまでは、CONTENT_DIR にダミー内容を指定します。そろったら CONTENT_DIR を外します。

判断は SSE で数十秒続きます。タイムアウトは 300 秒あれば足ります。

デプロイ後に表示される URL を、Vercel の NEXT_PUBLIC_AGENT_URL に入れます。

環境変数

名前既定説明
PORT8787待ち受けるポートです。
JUDGE_MODEキーの有無で決まるclaude か deterministic を指定します。公開では明示します。
ANTHROPIC_API_KEYなしClaude API のキーです。秘密の置き場所から渡します。
CONTENT_DIRリポジトリのルート知見とシナリオの置き場所です。相対パスはルートから解決します。公開では知見がそろうまでダミー内容を指定します。

API キーの管理

  • キーはエージェントの環境変数だけに置きます。
  • Cloud Run では Secret Manager から渡します。
  • Vercel にはキーを登録しません。画面はキーを必要としません。
  • NEXT_PUBLIC_ の付いた名前にキーを入れることは禁止です。
  • .env のファイルはコミットしません。イメージにも入れません。
  • Anthropic Console で利用額の上限を設定します。
  • 漏れた疑いがあれば、キーを無効にして作り直します。

.dockerignore は .env* をビルドの文脈から除きます。

CORS と頻度制限

CORS

CORS_ORIGINS には画面の本番オリジンだけを入れます。

オリジンは https:// から始め、末尾のスラッシュを付けません。

プレビュー用の URL はデプロイごとに変わります。必要なときだけ一時的に足します。

* は指定しません。他のサイトから API キーの費用を使われるためです。

頻度制限

エージェントは /judge をクライアントごとに 1 分単位で数えます。

上限を超えると、状態 429 の error イベントを返します。

TRUST_PROXY=true のときだけ、X-Forwarded-For の先頭の値で数えます。

それ以外では接続元のアドレスで数えます。

Cloud Run の背後では、全員が同じアドレスに見えます。そのため TRUST_PROXY=true にします。

プロキシを通さず直接受けるときは false にします。true だと利用者がヘッダを偽れるためです。

カウンタはインスタンスごとのメモリにあります。台数が増えると上限も増えます。

当面は次の対策を重ねます。

  • --max-instances を小さく保ちます。
  • 必要なら手前のロードバランサで IP ごとの制限をかけます。
  • Anthropic Console の利用額の上限を最後の防壁にします。

ローカルでの確認

リポジトリのルートで次を実行します。既定は決定論モードとダミー内容です。

docker compose -f infra/compose.yaml up --build

別の端末で、生存確認と判断の SSE を確かめます。

curl http://localhost:8787/health

curl -N -X POST http://localhost:8787/judge \
  -H 'content-type: application/json' \
  -d '{"observations":[],
       "newInput":{"type":"text","text":"JR京都線は人身事故の影響で、大阪駅〜京都駅間で運転を見合わせています。"},
       "origin":{"kind":"station","name":"大阪"},
       "destination":{"kind":"station","name":"京都"},
       "constraints":{"deadline":"2026-11-06T00:25:00+09:00","knowsAlternatives":false,"mobilityNotes":null},
       "language":"ja","now":"2026-11-05T22:12:00+09:00"}'

最後に judgment_ready のイベントが届けば成功です。

Claude を使うときは、ホストで ANTHROPIC_API_KEY を設定して起動します。

JUDGE_MODE=claude docker compose -f infra/compose.yaml up

公開前の確認リスト

表示

  • 判断の画面に、推定である旨の注意書きが出ています。
  • 注意書きに、公式発表を優先する旨が含まれています。
  • 地図の隅に出典が出ています。
  • 「このアプリについて」に、全データの出典が並んでいます。
  • 出典は docs/data-sources.md の 4 章と一致しています。

ログと秘密

  • 判断を数回流し、エージェントのログを読みます。
  • ログに入力の文面、画像、現在地が残っていません。
  • Vercel のログにも入力が残っていません。
  • 画面の配信物に API キーが含まれていません。
  • NEXT_PUBLIC_JUDGE_MOCK が本番で未設定です。

動作

  • JUDGE_MODE=deterministic で判断が最後まで届きます。
  • JUDGE_MODE=claude で判断が最後まで届きます。
  • 本番の画面から判断を流し、CORS で止まりません。
  • 上限を超えて送ると、状態 429 が返ります。
  • 起動ログの知見の件数と、読めなかった件数を確かめます。
  • CONTENT_DIR が本番の意図どおりの内容を指しています。

リポジトリ

  • pnpm typecheck、pnpm lint、pnpm test が通ります。
  • pnpm guard が通ります。
  • pnpm --filter @repo/web build が警告なく通ります。

全体構成

利用者のブラウザ→ 画面 apps/web　Vercel
利用者のブラウザ→ POST /judge と SSE → 判断エージェント apps/agent　Cloud Run→ Claude API

ブラウザはエージェントへ直接つなぎ、判断を SSE で受け取ります。

API キーを持つのはエージェントだけです。画面はキーを一切持ちません。

キーは Secret Manager に置き、Cloud Run が環境変数として渡します。

始める前に

  • gcloud に自分のアカウントでログインしてあること。
  • Cloud Run、Cloud Build、Secret Manager、Artifact Registry の API が有効なこと。
  • Anthropic Console で月の利用額の上限をかけてあること。
  • 公開したいコミットが GitHub に push 済みなこと。Vercel は GitHub から取り込みます。

最初に、以後のコマンドで使う値を端末に入れます。

gcloud config set project project-513d85ec-389b-42f9-b12
export PROJECT_ID=project-513d85ec-389b-42f9-b12
export REGION=asia-northeast1

手順 1　キーを Secret Manager に入れる

キーは標準入力から渡します。コマンドの文字列にキーを書かないので、履歴に残りません。

1 行目を実行すると入力待ちになります。キーを貼って Enter を押します。画面には表示されません。

printf 'Anthropic の API キーを貼って Enter: '; read -rs ANTHROPIC_KEY_INPUT; echo
printf '%s' "$ANTHROPIC_KEY_INPUT" | gcloud secrets create anthropic-api-key \
  --replication-policy automatic --data-file=-
unset ANTHROPIC_KEY_INPUT

Cloud Run と Cloud Build が使うサービスアカウントに、権限を渡します。

どちらも既定の Compute Engine のサービスアカウントです。

PROJECT_NUMBER=$(gcloud projects describe "$PROJECT_ID" --format 'value(projectNumber)')
SA="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"
gcloud secrets add-iam-policy-binding anthropic-api-key \
  --member "$SA" --role roles/secretmanager.secretAccessor
gcloud projects add-iam-policy-binding "$PROJECT_ID" \
  --member "$SA" --role roles/cloudbuild.builds.builder

キーを差し替えるときは gcloud secrets versions add anthropic-api-key --data-file=- を同じ形で使います。

差し替えた後は、手順 5 のコマンドで出し直します。

手順 2　Cloud Run に出す

infra/deploy-agent.sh が、ビルドから公開までを 1 回で行います。

この時点では画面の URL が無いので、CORS には手元の画面だけを入れます。

CORS_ORIGINS=http://localhost:3000 bash infra/deploy-agent.sh

台本は次の順に動きます。

  1. Artifact Registry に kansai の置き場所が無ければ作ります。
  2. infra/cloudbuild.yaml で Cloud Build を動かし、イメージを作って送ります。
  3. gcloud run deploy で kansai-agent を出します。
  4. 最後に公開 URL を表示します。

イメージのタグは今のコミットの短い SHA です。

送るファイルは .gcloudignore で絞っています。秘密のファイルと依存は送りません。

CORS_ORIGINS は毎回必ず渡します。渡さないと台本は止まります。

出し直しで画面のオリジンが消えるのを防ぐためです。

手順 3　生存を確かめる

AGENT_URL=$(gcloud run services describe kansai-agent --region "$REGION" --format 'value(status.url)')
echo "$AGENT_URL"
curl -s "$AGENT_URL/health"

{"status":"ok"} が返れば成功です。

起動ログで、判断モードが claude になっていることも確かめます。

gcloud run services logs read kansai-agent --region "$REGION" --limit 20 | grep 'agent listening'

mode: claude と出ていれば、キーが渡っています。

表示した AGENT_URL は手順 4 で使います。

手順 4　Vercel で取り込む

Vercel のダッシュボードで Add New から Project を選びます。

GitHub の ryomac5/built-with-claude-2026-japan を取り込みます。

手順 5　CORS に画面の URL を入れる

手順 4 で控えた本番の URL を入れて、エージェントを出し直します。

CORS_ORIGINS=https://YOUR-APP.vercel.app bash infra/deploy-agent.sh

YOUR-APP は自分の値に置き換えます。https:// から始め、末尾のスラッシュを付けません。

独自ドメインも使うなら、カンマで区切って並べます。

入ったかどうかは、次のコマンドで確かめます。

curl -s -i -X OPTIONS "$AGENT_URL/judge" \
  -H 'Origin: https://YOUR-APP.vercel.app' \
  -H 'Access-Control-Request-Method: POST' | grep -i access-control-allow-origin

画面の URL が返れば成功です。

手順 6　画面で判断を確かめる

  1. Vercel の本番 URL を開きます。
  2. 状況を入れて、判断を 1 回出します。
  3. 最後まで結論が出れば成功です。

止まったら、ブラウザの開発者ツールで CORS のエラーが出ていないかを見ます。

エージェント側の記録は次のコマンドで読みます。

gcloud run services logs read kansai-agent --region "$REGION" --limit 50

Cloud Run の設定値

値は infra/deploy-agent.sh に書いてあります。環境変数で上書きできます。

項目値理由
リージョンasia-northeast1利用者に近い東京です。
サービス名kansai-agent上書きは SERVICE で行います。
待ち受けのポート8080Cloud Run が PORT で渡し、エージェントはそれで待ち受けます。
要求の上限時間600 秒SSE を途中で切らないためです。判断は通常 1 分前後で終わります。
同時に受ける数20判断は Claude の応答待ちが主です。1 台で並べて受けられます。
最小インスタンス数0待機中の費用をかけません。審査の期間だけ 1 にすると、最初の応答が速くなります。
最大インスタンス数2使いすぎを防ぎます。頻度制限は台数ぶん緩むので、小さく保ちます。
CPU とメモリ1 と 512Mi起動を速めるため CPU ブーストを付けます。
認証認証なしブラウザから直接呼ぶためです。守りは CORS と頻度制限です。

例えば審査の期間に最小インスタンス数を 1 にするには、次のように出します。

MIN_INSTANCES=1 CORS_ORIGINS=https://YOUR-APP.vercel.app bash infra/deploy-agent.sh

環境変数

エージェントが読む環境変数です。Cloud Run には台本が渡します。

名前公開での値説明
PORTCloud Run が渡す待ち受けるポートです。手元の既定は 8787 です。
JUDGE_MODEclaude未設定ならキーの有無で決まります。公開では明示します。
ANTHROPIC_API_KEYSecret Manager からClaude API のキーです。
CORS_ORIGINS画面の本番オリジンカンマ区切りで複数指定できます。
RATE_LIMIT_PER_MINUTE61 分あたりに 1 利用者へ許す /judge の回数です。アプリの既定は 20 です。
TRUST_PROXYtrue利用者を X-Forwarded-For で見分けます。Cloud Run では必須です。
CONTENT_DIR設定しないシナリオの置き場所です。未設定ならイメージ内の scenarios/ を読みます。

頻度制限と使いすぎの防止

頻度制限

エージェントは /judge を利用者ごとに 1 分単位で数えます。

上限を超えると、状態 429 の error イベントを返します。

公開では 1 分に 6 回とします。人が画面から送る速さなら足ります。

Cloud Run の背後では、接続元が全員同じに見えます。そのため TRUST_PROXY=true にします。

カウンタはインスタンスごとのメモリにあります。台数が増えると上限も増えます。

X-Forwarded-For の先頭は利用者が偽れます。頻度制限は一次の守りにすぎません。

守りの重ね方

  • 最大インスタンス数を 2 に保ちます。
  • CORS は画面の本番オリジンだけを許します。* は指定しません。
  • Anthropic Console の利用額の上限を最後の防壁にします。

キーの扱い

  • キーは Secret Manager だけに置きます。
  • NEXT_PUBLIC_ の付いた名前にキーを入れることは禁止です。
  • .env のファイルはコミットしません。イメージにも入れません。
  • 漏れた疑いがあれば、Anthropic Console でキーを無効にします。新しいキーを手順 1 の形で入れ直します。

手元での確認

公開前に、同じイメージを手元の docker で確かめられます。キーは渡しません。

docker build -f infra/agent/Dockerfile -t kansai-agent:local .
docker run -d --name kansai-agent-local -p 18080:8080 \
  -e PORT=8080 -e JUDGE_MODE=deterministic -e TRUST_PROXY=true \
  -e CORS_ORIGINS=http://localhost:3000 kansai-agent:local
curl -s http://localhost:18080/health
curl -s -N -X POST http://localhost:18080/judge \
  -H 'content-type: application/json' \
  -d '{"observations":[],
       "newInput":{"type":"text","text":"JR京都線は人身事故の影響で、大阪駅〜京都駅間で運転を見合わせています。"},
       "origin":{"kind":"station","name":"大阪"},
       "destination":{"kind":"station","name":"京都"},
       "constraints":{"deadline":"2026-11-06T00:25:00+09:00","knowsAlternatives":false,"mobilityNotes":null},
       "language":"ja","now":"2026-11-05T22:12:00+09:00"}'
docker rm -f kansai-agent-local

最後に judgment_ready のイベントが届けば成功です。

docker compose -f infra/compose.yaml up --build でも同じ確認ができます。こちらは 8787 で待ち受けます。

困ったとき

症状見るところ
Cloud Build が権限の不足で止まる手順 1 の roles/cloudbuild.builds.builder の付与を確かめます。
出し直しで、シークレットを読めないと出る手順 1 の secretAccessor の付与を確かめます。
起動ログが mode: deterministic になるキーが渡っていません。--set-secrets の名前を確かめます。
画面で判断が始まらないCORS か NEXT_PUBLIC_AGENT_URL の誤りです。手順 5 のコマンドで確かめます。
判断が途中で止まるエージェントの記録を読みます。429 なら頻度制限です。

公開前の確認リスト

表示

  • 判断の画面に、推定である旨の注意書きが出ています。
  • 注意書きに、公式発表を優先する旨が含まれています。
  • 地図の隅に出典が出ています。
  • 「このアプリについて」に、全データの出典が並んでいます。

ログと秘密

  • エージェントのログに、入力の文面と画像と現在地が残っていません。
  • 画面の配信物に API キーが含まれていません。
  • NEXT_PUBLIC_JUDGE_MOCK が本番で未設定です。
  • Anthropic Console で月の利用額の上限がかかっています。

動作

  • 本番の画面から判断を流し、CORS で止まりません。
  • 起動ログに mode: claude と出ています。
  • 起動ログの読めなかった件数が 0 です。

リポジトリ

  • pnpm typecheck、pnpm lint、pnpm test が通ります。
  • pnpm guard が通ります。
  • pnpm --filter @repo/web build が通ります。

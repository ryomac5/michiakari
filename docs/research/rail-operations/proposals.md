# アプリの機能に落とす案

調査の結果から、アプリに足せる案を効き目の大きい順に並べる。
数値が要る案は、値を開発者の推定として規則表に置く。
公表値がある場合だけ、出典を規則表の注に添える。
利用者に事象の段階の名前や説明は出さない。
画面には、行動と見込みだけを出す。

## 一覧

| 順 | 案 | 根拠 | 作業の大きさ |
| --- | --- | --- | --- |
| 1 | 振替の費用を乗車券の種類で分ける | 05 | 中 |
| 2 | 線路への降車の手がかりで見込みを止める | 06、09 | 小 |
| 3 | 運転整理の放送の手がかりを足す | 02、03、08 | 小から中 |
| 4 | 発表の再開見込み時刻を優先する | 09 | 中 |
| 5 | 天気の事象は点検の後に再開とみなす | 04 | 小から中 |
| 6 | 直通運転の表で他社線の事象を扱う | 08 | 中から大 |
| 7 | 再開の後に残る遅れを到着時刻に足す | 03、07 | 中 |
| 8 | 地震の後に次の駅へ進む列車を見分ける | 04、06 | 小 |
| 9 | 防護無線の規則に公開の出典を添える | 01 | 小 |

## 1. 振替の費用を乗車券の種類で分ける

- 根拠の項目は、05 の関西の共通の扱いと対象の乗車券である
- 関西の 18 の事業者では、改札に入った後の IC 乗車券は振替の対象外である
- 定期券ときっぷは、止まった区間を含めば対象になる
- 規則表には、乗車券の種類ごとの振替の可否を置く
- 置き場所は `packages/core/params/transit.ts` が候補である
- `JudgeRequest` に乗車券の種類を足すと、`packages/schema` の変更になる
- 入口と判断の両方の WS に影響する
- 画面では、振替の選択肢の運賃を乗車券の種類で変える
- IC の残額の利用者には、振替先の運賃がかかると出す
- 計画運休の発表に振替なしとあれば、振替の選択肢を出さない
- 作業は中である。入力の項目、スキーマ、運賃の計算、画面の文言に及ぶ

## 2. 線路への降車の手がかりで見込みを止める

- 根拠の項目は、06 の線路へ降りる判断と、09 の再開の見込みが出ない場合である
- 降車の誘導を始めると、再開が遅れ、見込みも示しにくくなる
- 規則表には、新しい手がかりの id を足す
- 候補は `track_evacuation` で、線路に降りて避難、降車誘導、はしごの語で拾う
- id は `ANNOUNCEMENT_CUE_IDS` に、言い回しは `ANNOUNCEMENT_CUE_PATTERNS` に置く
- この手がかりがあれば、`rare` と同じく数字を言い切らない
- 画面では、待つ選択肢の時刻を出さない
- 係員の案内に従うことを最初の行動として出す
- 降りた後の駅からの経路を、次の一手として示す
- 作業は小である。手がかりの追加と、見込みを止める分岐で済む

## 3. 運転整理の放送の手がかりを足す

- 根拠の項目は、02 の手段と兆候、03 の徐行、08 の直通の中止である
- 規則表には、次の手がかりの id を足す

| id の候補 | 拾う語 | 判断での使い方 |
| --- | --- | --- |
| `turnback` | 折り返し運転 | 折り返しの駅までは列車で進めるとみなす |
| `terminated_here` | この列車は運転を取りやめ | その駅で降りて切り替える選択肢を上げる |
| `through_cancelled` | 直通運転を中止 | 接続駅での乗り換えを前提にする |
| `slow_running` | 徐行運転 | 再開の後の遅れを見込みに足す |
| `held_at_station` | しばらく停車、抑止 | 駅にいるので、降りて切り替えられるとみなす |

- 画面では、選択肢の並びと到着時刻にだけ反映する
- 拾った語の意味を説明する文は出さない
- 作業は小から中である。id ごとに判断の分岐とテストが要る

## 4. 発表の再開見込み時刻を優先する

- 根拠の項目は、09 の発表の更新である
- 国土交通省は、再開の見込み時刻をできる限り具体的に示すよう求めている
- 次の更新の予定時刻を添えることも望ましいとしている
- 発表文から時刻を取り出す処理を、解釈の段に足す
- 取り出した時刻は、`ResumeChance` の見込みより優先する
- 次の更新の時刻は、待つかを決め直す時刻として持つ
- 画面では、再開の見込みに発表の時刻を出す
- 次の発表の時刻を、決め直す目安として出す
- 作業は中である。時刻の取り出し、スキーマ、判断の優先順位に及ぶ

## 5. 天気の事象は点検の後に再開とみなす

- 根拠の項目は、04 の共通の流れである
- 雨量や風速が下がっても、点検が終わるまで再開しない
- 雨は止んだ後も、斜面が水を含めば規制を続けることがある
- 風は収まった後も、突風に備えて一定の時間は見合わせを続けることがある
- 規則表の `INCIDENT_BEHAVIOR` に、点検を待つかの項目を足す
- 対象は `heavy_rain`、`strong_wind`、`earthquake` である
- 気象の読み取りが良くなっても、点検の時間を引かずに見込みを残す
- 湖西線と北陸線の防風柵の区間は、見合わせが短い傾向に寄せられる
- 画面では、雨や風が止んでもすぐには動かない見込みを出す
- 作業は小から中である。点検の時間の値は開発者の推定が要る

## 6. 直通運転の表で他社線の事象を扱う

- 根拠の項目は、08 の関西の主な直通運転と、直通を止める扱いである
- 直通を止めると、事業者ごとに折り返す
- 境の駅で折り返せないと、離れた区間も運休になる
- 規則表に、直通の組と接続駅の表を新しく置く
- 置き場所は `packages/core/params/` の新しいファイルが候補である
- 境の駅で折り返せるかは公開の資料が無く、開発者の材料が要る
- 他社線の事象では、自分の線は接続駅の手前まで動く見込みを出す
- 画面では、接続駅までは今の線で進める選択肢を出す
- 作業は中から大である。路線データとの突き合わせと、止まる範囲の計算に及ぶ

## 7. 再開の後に残る遅れを到着時刻に足す

- 根拠の項目は、03 の再開の後の徐行と、07 の人身事故の手順である
- 豪雨と地震の後は、再開の後も徐行することがある
- 朝夕のラッシュ時は、正常ダイヤに戻るまで時間がかかる
- 夜間の人身事故は、救出と捜索にさらに時間がかかることがある
- 規則表に、再開の後の遅れの幅を事象の種類ごとに置く
- 時間帯で、ラッシュと夜間の補正を掛ける
- 値は公表値が無いので、開発者の推定とする
- 画面では、待つ選択肢の到着時刻の幅を広げる
- 作業は中である。到着時刻の計算と、比べる処理に及ぶ

## 8. 地震の後に次の駅へ進む列車を見分ける

- 根拠の項目は、04 の地震と、06 の駅へ進む扱いである
- JR西日本と阪急は、安全を確かめた区間の列車を次の駅まで進める
- 電車の中の利用者は、次の駅で降りられる見込みがある
- `estimateStopReasons` と同じく、電車の中の判断に分岐を足す
- 揺れの強さの入力は無いので、手がかりの id で受ける
- 候補は、徐行で次の駅まで、の放送である
- 画面では、次の駅で降りた後の選択肢を先に示す
- 作業は小である。既存の次の駅の計算を使える

## 9. 防護無線の規則に公開の出典を添える

- 根拠の項目は、01 の届く範囲と解除までの流れである
- 公開資料は、届く範囲を半径およそ 1km から 2km としている
- 受信した列車は、指令の確認の後に動く
- 規則表の `PROTECTION_RADIUS_KM` の注に、公開の出典を添える
- `INCIDENT_BEHAVIOR_SOURCE` は開発者の推定のまま残す
- 他社の列車が止まらないという前提は、公開資料では確かめられない
- この前提は、開発者に確かめてから注に書く
- 画面は変えない
- 作業は小である。注の追記と、開発者への確認で済む

# 画面設計（UX）

## 1. 設計原則

1. **結論を一つだけ大きく出す。** 急いでいる人が最初の1秒で行動を決められること
2. **根拠は見たい人だけが開ける。** 既定では閉じておく
3. **考えている過程が見える。** 判断を待つ間、読み取り・兆候の検出・段階の推定が順に現れる
4. **入力は最小限から。** 最初は「いる駅」と「行き先」だけ。制約は必要になったときに聞く
5. **推定であることを常に示す。** 結論の近くに注意書きを常時表示する
6. **色だけに頼らない。** 止まっている区間などは、色に加えて線種・ラベルでも示す

## 2. 画面構成

### 2.1 開始

- 現在地の取得ボタン、または駅の検索
- 行き先の入力（駅名・地名）
- 言語の切り替え（日本語／English）

### 2.2 状況の入力

- 撮影する（掲示・画面）
- 貼り付ける（発表文）
- 選んで答える（事象の種類 → 聞こえた案内の内容を選択式で）

### 2.3 判断（中心となる画面）

上から順に:

1. **結論カード**: 「あと25分は待てます」「いま振替に切り替えてください」など。推定である旨を下に小さく
2. **分岐点**: 「21:40までに再開しなければ、振替のほうが早く着きます」。現在時刻からの残り時間を表示
3. **地図**: 実距離の路線図（3章）
4. **選択肢**: 待つ／振替／タクシーなど、それぞれの到着時刻・運賃・徒歩時間
5. **根拠**（開閉式）: 段階のタイムラインと「いまここ」、検出した兆候と対応する知見
6. **情報を追加**: 新しい掲示・発表を入力すると判断を更新

判断の生成中は、結論カードの位置に推論の過程（読み取り → 兆候 → 段階 → 選択肢 → 分岐点）を順に表示する。

### 2.4 行動

- 選んだ選択肢の道順を地図に表示（徒歩経路、乗る路線と駅）
- 振替輸送を使う場合の利用条件（対象となる乗車券、乗り換え時の手順）

### 2.5 このアプリについて

- 目的、推定の考え方、出典表示、注意事項

## 3. 地図の仕様

- 実距離の路線図。デフォルメしない
- 現在地を中心に、選択肢になる範囲を自動で拡大表示する。全域表示は既定にしない
- レイヤー:
  - 止まっている区間（強調色＋破線）
  - 現在地から徒歩10分・20分の到達範囲
  - 到達範囲内の、動いている別路線の駅（強調）
  - 振替輸送の対象路線
  - 推奨する経路
- 路線の色は各社のラインカラーに合わせる。ラインマーク・ロゴは使わない
- 駅が密集する地区（梅田、難波、京橋、天王寺、三宮など）ではラベルの重なりを避ける

## 4. リプレイモード

- シナリオを選ぶと、時刻を早送りしながら観測を順に入力する
- 観測が入るたびに判断・タイムライン・地図が更新される
- 再生・一時停止・速度変更ができる
- デモ動画の撮影に使う（Playwright による自動操作に対応できるよう、各操作に安定したセレクタを付ける）

## 5. 対応環境

- スマートフォンの縦画面を最優先。PC でも崩れないこと
- 文字は大きめ。屋外・駅構内の明るさでも読めるコントラスト

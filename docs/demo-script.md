# デモ動画の台本（3分）

## 方針

- 冒頭は開始画面の導入を25秒映す
- 導入の3行をそのままナレーションに使う
- アプリの部分は必ず実際の画面を録画する（リプレイモード＋Playwright の自動操作）
- ナレーションは開発者本人の声
- 期間中に作った機能だけを紹介する

## 構成

| 時間 | 映像 | ナレーションの要点 |
|---|---|---|
| 0:00〜0:25 | 開始画面で利用者・課題・解決の3行と駅の入力欄を見せる | 下記の導入をそのまま読む |
| 0:25〜0:45 | 掲示を撮影 → 推論の過程が順に現れる → 結論と分岐点 | 掲示を撮るだけで、いまの段階と、待つか切り替えるかが分かる |
| 0:45〜1:30 | リプレイ: 発表が更新されるたびに、タイムラインの「いまここ」、分岐点、地図が変わる。分岐点を越えた瞬間に「切り替えてください」へ | 状況が動くたびに判断が更新される |
| 1:30〜1:50 | 地図: 止まっている区間、徒歩の到達範囲、動いている別路線、推奨経路 | 実距離の地図で、いまどこに選択肢があるかが一目で分かる |
| 1:50〜2:05 | 別の事象（大雨）で経過がまったく違うことを短く | 事象ごとに、指令員が見ている兆候は違う |
| 2:05〜2:35 | 画面の根拠表示で、判断に使った兆候と段階を見せる。知見は画面に出さず、判断の裏側で使っていると伝える | このアプリの判断の根拠は、指令員の経験を一般化した知見 |
| 2:35〜3:00 | 判断に従った人と待ち続けた人の到着時刻の比較。英語画面も一瞬 | 本来、誰にでも届くべき判断材料を、すべての利用者に |

## 冒頭の導入

関西で鉄道の運転見合わせに遭い目的地への移動に困っているすべての利用者に向けたアプリです。

何が起きたかを伝える運行情報だけでは待つか別の路線に乗り換えるかを判断する材料が足りません。

元指令員の知見をもとに再開までの見込みから待つか乗り換えるかを決めるための行動を示します。

画面では利用者・課題・解決を1行ずつの段落で示す。
スマートフォンでは読みやすさのために各段落を折り返す。
推定である旨と公式発表を優先する注意書きも同じ画面に残す。
録画の切り出し開始は導入と地図の描画後に置く。

## 撮影の準備

- デモ用シナリオ: 人身事故（終電間際）、大雨
- 端末: スマートフォンの縦画面サイズで録画
- 録画: Playwright で操作を自動化し、何度でも同じ品質で撮り直せるようにする
- 編集: 説明パート（知見ナレッジ → 推論 → 判断の流れ）は図解アニメーション

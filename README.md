# みちあかり

関西で電車が止まったとき、いま取れる選択肢と、その見込みを示す Web アプリです。
Built with Claude: Japan 2026 ハッカソンの提出作品です。

> Michiakari is a web app for rail passengers in Kansai caught in a service disruption.
> It shows the options they have right now and the outlook for each one.
> It estimates the time to resumption, a break-even time, and a concrete next action.
> The rules come from a former train dispatcher's experience, rewritten as observable signs.
> Every number is computed by code, and Claude interprets, chooses, and explains.
> It runs without an API key in a deterministic mode, and it never scrapes operator data.

## 課題

電車が止まると、不安な時間が始まります。
いつ頃動くのか、このまま待っていて大丈夫なのか。
約束や乗り継ぎの時刻に間に合うのかも、気がかりです。

運行情報は、何が起きているかを、その場の全員に向けて伝えます。
けれど、自分はどうすればよいかは、行き先や急ぎ具合によって人ごとに違います。
その答えを、聞いた放送や掲示から一人で探すのは心細いものです。

私は鉄道の指令員として働いていました。
電車が止まると、現場で何が起きていて、何を確かめれば安全に運転を再開できるのかが、おおよそ分かります。
その見当を、不安な時間を過ごす人の手元に届けたいと考えました。

みちあかりは、その経験を外から見える兆候の規則に置き換えました。
止まったその場で、いま取れる選択肢と見込みを示し、次の一歩を照らします。
示すのは推定です。
公式の案内を優先したうえで、自分で決めるための手がかりにしてほしい。
みちあかりは、その願いから作りました。

## 返すもの

| 返すもの | 内容 |
|---|---|
| 見込み | 再開までの残り時間を幅で示します。 |
| 分岐点 | この時刻までに動かなければ、別の経路のほうが早く着く境目です。 |
| 行動 | いま取る行動を一文で言い切り、勧める経路を地図に描きます。 |

判断にはいつも、使った手がかりと規則を根拠として添えます。

## 利用の流れ

会員登録は要らず、止まったときに開けば使えます。

1. 開くと関西の地図が出て、駅にいるか、駅と駅の間で止まっているかを尋ねます。
2. 駅は丸を押して選びます。駅の間は線を押すと候補が光ります。
3. 現在地を答えたら行き先を選びます。乗る路線と方面は候補が一つなら省きます。
4. 起きていることを選びます。掲示を撮るか、発表文を貼り付けてもかまいません。
5. 判断の画面に移り、行動の見出しと理由が 1 行ずつ出ます。
6. シートを引き上げると、再開の見込みの図と根拠を読めます。
7. 新しい発表を足すと、判断と地図が描き直されます。

リプレイでは、架空のシナリオの発表を時刻順に流します。
判断と地図が変わっていく様子を、操作なしで見られます。

## 主な機能

| 機能 | 内容 |
|---|---|
| 状況の入力 | 掲示の撮影、発表文の貼り付け、選択式の 3 通りで伝えます。 |
| 線の押下 | 最初の地図で線を押すと、駅の間の候補が地図の上で光ります。 |
| 見込みの図 | 再開の見込みを時刻の軸の 1 枚の図にし、分岐点に印を付けます。 |
| 受信の放送 | 車内の人に、非常停止の信号を受けたという放送を聞いたか尋ねます。 |
| 防護無線 | 周りの列車が一斉に止まる事象では、止まらない他社の路線を先に勧めます。 |
| 反対の線路 | 反対の線路は確かめが済めば先に動くことがある、と見込みを分けて示します。 |
| 再開後の詰まり | 動き出しても前の列車が詰まる分を見積もります。次の駅で降りる価値も示します。 |
| 止まった理由 | 車内の人に、列車が止まったいちばん有力な理由を 1 行で示します。 |
| 駅の間の車内 | 次の駅に着いてから何をするかで結論を書きます。 |
| 徒歩の到達範囲 | 徒歩 10 分と 20 分の範囲を描き、範囲内で動いている別路線の駅を示します。 |
| 推論過程の表示 | 判断を待つ間、読み取りから分岐点までの各段を順に出します。 |
| リプレイ | 架空のシナリオを再生し、判断が変わった瞬間を 1 枚のカードで知らせます。 |

画面は日本語と英語に対応し、スマートフォンの縦画面を優先しています。

## 判断の材料

判断の材料は次の 3 つに限っています。

- 事象の種類ごとの振る舞いを書いた規則表
- 報道に残った事例から求めた、運転見合わせの所要時間の統計値
- 利用者が持ち込んだ発表と放送

規則表は、元指令員の経験を開発者が規則に落としたものです。
規則は社内の数値ではなく、外から観察できる兆候で定義しています。
たとえば止まり方を、その列車だけ、その列車から、区間ごとの 3 つに分けています。
経験を書き留めた材料はリポジトリに入れず、実行時にも読みません。
規則表の値には、出典として開発者の推定であることを明記しています。

規則表は `packages/core/params/incident-behavior.ts` の 1 か所にあります。
画面と判断は同じ表を引きます。
仕組みの詳細は [docs/architecture.md](docs/architecture.md) の 4.1 節にあります。

## Claude の役割

モデル名は `apps/agent/src/config.ts` の 1 か所で管理しています。

| 役割 | モデル | 使い方 |
|---|---|---|
| 観測の解釈 | `claude-haiku-5-5` | 掲示の写真や発表文を読み、構造化した観測にします。 |
| 判断 | `claude-opus-5-5` | 自前のツール実行ループで材料を集め、行動を選んで説明します。 |

判断ループのツールは次のとおりです。

- `get_weather` は気象庁アメダスの 10 分間降水量を引きます
- `estimate_remaining` は規則表と統計値から残り時間を見積もります
- `find_alternatives` は止まっている区間を避けた経路を探します
- `compute_break_even` は分岐点と時刻ごとの再開の見込みを計算します
- `emit_judgment` は判断を確定します

Claude に数値を作らせない作りにしています。

- 数値はすべて `packages/core` と `packages/geo` のコードが計算します
- Claude は行動の選択と根拠の説明を担います
- 文中の時刻、分、円はツールの結果と照合し、外れたら 1 回まで直させます
- 止まった理由は割合の数字を書かせず、言葉の強さで言い表させます
- 利用者の入力はシステムプロンプトに混ぜず、観測データとして渡します
- ツールの開始と結果、合間の進捗メモを SSE で画面へ流します
- Claude が失敗したら、済んだ手順を残して決定論の規則で仕上げます

公開サービスにファイル操作のツールは要りません。
イベントの粒度も細かく制御したいので、ループを自前で書いています。

## Claude Code での開発

開発は Claude Code を中心に進めました。
詳しくは [docs/guides/claude-code-usage.html](docs/guides/claude-code-usage.html) にあります。

- 根のエージェントが計画し、子のエージェントに実装を振ります。
- 実装と別系統のモデルがレビューし、盲点を共有しないようにしました。
- 並行する作業は worktree に分け、受け入れのコマンドで合否を決めました。
- `.claude/hooks/protect-paths.mjs` が、シナリオと非公開の材料への書き込みを止めます。
- `pnpm guard` が、シナリオの改変と、材料の文の写し込みを検出します。
- 利用者向けの文は [docs/agents/wording.md](docs/agents/wording.md) の決まりで書きました。
- 自律で作業するときの規則は [docs/goals.md](docs/goals.md) にあります。
- 各作業の記録は [docs/progress.md](docs/progress.md) に残しています。

## 検証

復旧時間の正解データは手に入りません。
そこで、振る舞いが正しい向きに出るかを 3 層で確かめています。

| 層 | 確かめること |
|---|---|
| 単体テスト | 分岐点、到着時刻、運賃、残り時間などの計算を Vitest で確かめます。 |
| 振る舞いテスト | シナリオの期待する振る舞いから Playwright のテストを生成します。 |
| 開発者の確認 | 画面を端末の大きさで撮り、開発者が目で確かめます。 |

e2e の spec は 34 ファイルあります。
コミットは 2026-11-07 の時点で 500 件を超えています。

## 構成

```
利用者の端末
  apps/web  Next.js / MapLibre GL JS
     │  POST /judge で観測の列と新しい入力を送る
     ▼
  apps/agent  Hono / Anthropic SDK
     │  1. 解釈     Haiku か文字列照合で観測にする
     │  2. 判断     Opus のツール実行ループか決定論の規則
     │  3. 検査     Zod のスキーマと数値の照合
     │
     ├─ packages/core    規則表、残り時間、分岐点、到着時刻、運賃
     ├─ packages/geo     路線・駅のネットワークと経路探索
     └─ scenarios/ の YAML
     │
     └─ SSE で判断イベントを返す ──▶ apps/web が逐次描画する

前処理
  国土数値情報 ──packages/data──▶ packages/geo/data の GeoJSON と JSON
```

| ディレクトリ | 役割 |
|---|---|
| `apps/web` | 開始、状況の入力、判断、リプレイの画面です。 |
| `apps/agent` | 判断エージェントです。`POST /judge` と `GET /health` を持ちます。 |
| `packages/schema` | 全境界の Zod スキーマです。型はここから導出します。 |
| `packages/core` | 規則表と決定論的な計算です。Claude を呼びません。 |
| `packages/geo` | 路線・駅の参照と、ネットワーク上の経路探索です。 |
| `packages/data` | DuckDB による前処理です。関西の路線 106 本と駅 1356 駅を出力します。 |
| `e2e` | Playwright による振る舞いテストとデモの録画です。 |

関西にはオープンな時刻表データがありません。
乗車時間は、駅間距離と路線種別ごとの速度から概算します。
徒歩時間は、事前に計算した経路が無ければ直線距離から概算します。
これらのパラメータは開発者の推定による仮の値です。

設計の詳細は [docs/architecture.md](docs/architecture.md)、画面は [docs/ux.md](docs/ux.md) にあります。

## 動かし方

Node.js 24 以上と pnpm 10 が必要です。

```bash
pnpm install
pnpm --filter e2e exec playwright install chromium
```

2 行目は、e2e と録画に使うブラウザを入れます。

### API キーなしの起動

API キーが無くても、エージェントは決定論モードで動きます。
解釈は文字列照合で、判断は規則で行います。
使えないのは写真の読み取りだけです。

```bash
pnpm dev:demo
```

画面とエージェントを、開発用のダミー内容で起動します。
http://localhost:3000 を開きます。
リプレイは http://localhost:3000/replay から始められます。
エージェントはポート 8787 で待ち受けます。

### claude モードの起動

`pnpm dev:demo` は、キーがあっても既定では決定論モードで動きます。
claude モードにするときは、キーを置いて `JUDGE_MODE=claude` を付けます。

```bash
export ANTHROPIC_API_KEY=<あなたのキー>
JUDGE_MODE=claude pnpm dev:demo
```

起動時のログに `mode: claude` と出れば有効です。
キーはエージェント側の環境変数にだけ置き、画面には渡しません。

### 環境変数

| 変数 | 対象 | 内容 |
|---|---|---|
| `ANTHROPIC_API_KEY` | agent | Claude の API キーです。 |
| `JUDGE_MODE` | agent | `claude` か `deterministic` を指定します。 |
| `CONTENT_DIR` | agent, web | シナリオの読み込み元です。リポジトリルートからの相対パスで書きます。 |
| `PORT` | agent | 待ち受けるポートです。既定は 8787 です。 |
| `CORS_ORIGINS` | agent | 許可するオリジンをカンマ区切りで書きます。 |
| `RATE_LIMIT_PER_MINUTE` | agent | 接続元ごとの 1 分あたりの上限です。既定は 20 です。 |
| `TRUST_PROXY` | agent | `true` のとき、頻度制限に `X-Forwarded-For` を使います。 |
| `NEXT_PUBLIC_AGENT_URL` | web | エージェントの URL です。既定は `http://localhost:8787` です。 |

### テスト

```bash
pnpm test
pnpm test:e2e
pnpm lint && pnpm typecheck
pnpm guard
pnpm validate:dev
```

`pnpm test` は全パッケージの単体テストを流します。
`pnpm test:e2e` は画面とエージェントを決定論モードで自動起動します。
`pnpm guard` はシナリオの改変と材料の文の写し込みを検査します。
`pnpm validate:dev` はダミーのシナリオの YAML を検証します。
`pnpm smoke:claude` は実 API で claude モードを 1 回だけ確かめます。

### 録画

```bash
pnpm --filter e2e record
```

スマートフォンの縦画面でリプレイを録画します。
動画は `e2e/recordings/` に出力され、git では管理しません。
場面の流れは [docs/demo-script.md](docs/demo-script.md) にあります。

## 推定の扱い

みちあかりの出力はすべて推定です。
判断結果には、推定である旨の注意書きが必ず付きます。
画面では結論の近くに、公式発表を優先するよう常に表示します。
見込みが立たないときは数字を言い切らず、分岐点を中心に示します。

## 運行情報の扱い

鉄道事業者の運行情報と列車走行位置は自動で取得しません。
スクレイピングや非公式の API も使いません。
運行情報は、利用者が撮影や貼り付け、選択で持ち込みます。
入力した内容と現在地は判断に使うだけで、保存しません。

## シナリオ

リプレイのシナリオは、開発者本人が `scenarios/` に書きます。
エージェントは読むだけで、フックが書き込みを止めます。
シナリオはすべて架空で、実在の事故記録や公式発表文は使いません。
書式は [scenarios/README.md](scenarios/README.md) にあります。

開発用のダミーは `packages/schema/test/fixtures/dev-content/` にあります。
画面とエージェントを動かすための仮の内容です。

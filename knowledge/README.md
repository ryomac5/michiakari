# 知見ナレッジ

元指令員である開発者の実務経験を、**外から観察できる兆候**にもとづいて一般化したもの。判断エージェントは、このナレッジを判断材料の一つとして参照する。

## 書き方の原則

- 社内の規制値、規程、内部手順の数値を書かない
- 兆候は、利用者が見聞きできる情報（発表文の文言、掲示、構内放送、雨量、列車の動き）で定義する
- 所要時間は「中央値」と「長引く場合（80%の事象がこの時間内に収まる目安）」の2つで書く
- 発表文の例は自作する。実在の発表文を転載しない

## ファイル構成

- 1事象1ファイル（例: `person_accident.yaml`, `heavy_rain.yaml`）
- 書式は `_template.yaml` を参照
- スキーマは `packages/schema` の `KnowledgeSchema` が正

## 事象の候補（優先順位は開発者が決める）

人身事故、車両故障、信号・ポイント故障、線路内立ち入り、踏切事故、大雨、強風、地震、停電・架線支障、急病人対応、他社線の影響
